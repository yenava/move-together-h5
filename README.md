# 跃动 · 一日会议健康 PK

面向手机与微信内浏览器的 H5。昵称报名、自选项目、自由组队、随时更新数据，晚饭投屏揭榜。React + Vite、Express、SQLite；无需安装客户端。

## 本次规则

当前验证配置 `ACTIVITY_TIME_LIMITS=false`：随时可报名、组队和打卡，不自动结榜。管理员仍可手动暂停、恢复、生成战报和最终结榜。恢复正式赛程时设为 `true`，采用 **2026-11-01 08:00–18:00（北京时间）**。

| 赛道 | 预设目标 | 成绩 |
| --- | --- | --- |
| 走路步数 | 8,000 步 | 当天累计步数 |
| 减重 | 1 斤 | 早晚体重差的绝对值，无论升降 |
| 增重 | 1 斤 | 早晚体重差的绝对值，无论升降 |
| 戒烟 | 8 小时 | 当天累计未吸烟时长 |
| 喝水 | 8 杯 | 水印拍照打卡，每次确认 +1 杯，一杯约 250 mL |

- 可选多个项目、之后追加报名。五赛道独立排名，按实际成绩降序，同成绩并列；目标用于展示进度，不跨项目混算积分。每个赛道可切换综合榜、个人榜、团队榜；综合榜将个人成绩与团队人均成绩一起排，行内标明类型及“/人”。首页、投屏和 CSV 导出同步支持。
- 步数、体重、戒烟重复填写覆盖旧值；喝水改为拍照累计，不再手填，原有累计杯数保留。体重单位斤，最多一位小数，晚称可稍后补；未完成早晚两次时成绩为 0。
- 一支战队固定一个项目，每队最多 5 人。同一项目每人最多加入一队，不同项目可加入不同战队。创建/加入自动报名对应项目，已有当天成绩直接计入；团队成绩＝全体队员成绩之和 ÷ 队员人数，未打卡记 0。
- 首次访问只填写昵称。未报名项目卡片提供个人参赛 / 加入战队 / 创建战队，已报名卡片直达打卡。组队广场按五项目切换，“我的”按项目展示个人或战队归属。邀请链接填写昵称后确认加入；旧队伍邀请提供拆分后的项目队伍选择。无独立 PK 对局。
- 参赛昵称与成绩公开；早晚体重原始值只给本人及管理员查看。匿名身份保存在浏览器 Cookie 中，换浏览器或清除数据无法恢复原身份。

## 本地使用

需要 **Node.js 24**（内置 node:sqlite）。

```bash
npm ci
npm run dev
```

页面：<http://localhost:5173>；API：<http://localhost:3001>。开发默认包含标注为体验的演示数据，数据保存在 `data/`。同 Wi-Fi 手机可访问 Vite 显示的 Network 地址；电脑需保持运行。

页面入口：`/#overview` 首页、`/#teams` 组队、`/#leaderboard` 分赛道榜单、`/#records` 我的、`/#admin` 管理、`/#screen` 实时投屏。其他设备每 15 秒刷新成绩。

## 管理与战报

管理员使用独立管理口令，参与者无需登录。环境变量 `ADMIN_KEY` 不填时，系统生成口令并保存到 **DATA_DIR/admin-key.txt**，只在本机读取，不公开。管理页可查看各赛道报名与打卡、原始记录，并执行：

1. 生成阶段战报：固定当前五赛道个人榜及团队人均榜，可选同时暂停。
2. 恢复活动：阶段榜保持不变，后续打卡继续更新实时榜。
3. 导出 CSV 或打开阶段榜投屏链接，链接携带 report 参数，可直接分享。
4. 最终结榜：锁定数据并生成最终榜，不能再恢复；启用时间限制后，到截止时间也自动执行。

投屏页支持切换五赛道、个人 / 团队榜、全屏与赛道自动轮播。**战报就是分赛道排行榜，没有 AI 文字解读。**

## 截图识别

`.env` 中配置 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_MODEL=deepseek-flash`。通过服务端调用官方 `https://api.deepseek.com/chat/completions` 图片接口，密钥不会发送给浏览器。未配置或服务异常时，仍可手动填写。

参与者上传微信运动 / 手机健康截图，前端压缩后先保存凭证，再发送识别；结果仅回填表单，必须核对日期、数值及单位后确认。体重 kg 自动转为斤。即使识别失败或之后修改数值，上传凭证仍会保留；截图会交给 DeepSeek 处理。识别不是防作弊审核，也不会验证参与者身份。

喝水使用手机相机拍摄，前端添加昵称、北京时间和“本次 1 杯”水印。预览并确认后，照片保存、杯数自动加 1；同一次提交重试不会重复计数。喝水照片不调用识别模型。

图片存放在持久化的 `DATA_DIR/evidence/`，不放入公开静态目录。本人可在录入弹层及“我的 → 我的打卡凭证”查看和下载；管理员在参与者记录的“核对凭证”列查看和下载。其他参与者和公开榜单无法访问图片。公开榜单只显示图片是否已留存：已提交成绩且有图片显示“图片打卡”，只有图片尚未提交成绩显示“图片已传 · 待提交”；战报保留生成时的标记。更新版本前上传但当时未保存的截图无法补回。

## 正式上线

本地预览不是公网链接。正式使用需要一台有持久化磁盘的 Node 服务器、域名及 HTTPS 反向代理。

已有 `.env` 时，请编辑需要的配置，保留已有密钥；初次部署可从 `.env.example` 创建。**正式活动必须选全新的 DATA_DIR 并关闭 SEED_DEMO，关闭开关不会删除旧演示数据。**

```bash
npm ci
npm test
npm run build
npm start
```

生产页面与 API 同源，默认端口 3001；npm 启动命令自动读取 `.env`。用 systemd 或容器托管进程，避免关闭终端后中断。

| 环境变量 | 配置 |
| --- | --- |
| DATA_DIR | 正式环境如 ./data-live，需持久化 |
| SEED_DEMO | 正式设 false |
| ACTIVITY_DATE | 2026-11-01 |
| ACTIVITY_TIME_LIMITS | 验证配置 false，关闭开场时间和自动结榜；true 恢复正式赛程 |
| ACTIVITY_OPEN / ACTIVITY_CLOSE | 08:00 / 18:00，北京时间，同一天 |
| ADMIN_KEY | 至少 8 字符；留空生成到数据目录 |
| DEEPSEEK_API_KEY | DeepSeek 官网密钥，仅服务端 |
| DEEPSEEK_MODEL | deepseek-flash，需支持图片输入 |
| PORT | 3001 |
| COOKIE_SECURE | 正式 HTTPS 设 true，本地 HTTP 设 false |
| BASE_PATH / COOKIE_PATH | 根路径默认 /；部署子路径时两项均设 /sports/，BASE_PATH 在构建时生效 |

Docker 配置已提供，部署示例（本机未执行容器构建）：

```bash
docker build -t move-together .
docker volume create move-together-data
docker run -d --name move-together --restart unless-stopped \
  --env-file .env -e DATA_DIR=/app/data -e SEED_DEMO=false \
  -p 127.0.0.1:3001:3001 -v move-together-data:/app/data move-together
```

同机 Caddy 示例，将域名替换成自己的，DNS 指向服务器并开放 80 / 443：

```caddyfile
sport.example.com {
  encode gzip
  reverse_proxy 127.0.0.1:3001
}
```

仅静态托管或临时文件系统不适用。单个 Node 实例运行；备份时停服务，复制整个 DATA_DIR（包括 SQLite 附属文件和 evidence 图片目录）后再启动。不要在活动开始后改日期或重新初始化数据。

上线后用两部手机验证报名、入队、截图识别、榜单同步及微信转发，再将正式 HTTPS 链接发到群。分享使用 Web Share / 复制链接；微信可右上角转发，未配置 JSSDK 自定义卡片。
