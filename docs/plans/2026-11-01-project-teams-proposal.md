# 项目与战队交互调整建议（已确认）

## 当前问题

现有 users.team_id 将一个人绑定到全活动唯一的战队。战队没有固定项目，展示的项目标签与榜单由成员报名的项目动态汇总。首次进入又要求先选个人或组队、之后才报名项目，导致用户加入队伍时无法明确参加什么比赛。

## 推荐规则

- 一支战队固定关联一个项目，创建后不切换项目；每队最多 5 人，不满 5 人也能参赛。
- 同一人在同一项目最多加入一支战队；不同项目可加入不同战队，也可个人参与。
- 参赛方式按项目决定，不再是首次进入时的全局属性。
- 加入战队自动报名对应项目；创建战队自动将创建者加入并报名。均以事务处理，满员时不留下部分报名状态。
- 已报名、已打卡的用户加入本项目战队时，直接沿用当天已有成绩；不要求再打卡。
- 个人成绩始终参与该项目个人榜；加入战队后同一成绩用于计算本项目团队人均。
- 综合榜继续以当前项目的个人成绩和团队人均一起排名，不跨项目计算。
- 活动进行中报名后仍可加入本项目战队，加入确认时明确提示已有当天成绩计入；暂不增加自由退队、换队功能。暂停或最终结榜遵循现有管理控制。

## 页面与流程

1. 首次进入只填写昵称，完成后直达首页。邀请链接携带具体战队，填写昵称后直接展示该战队项目、队名、人数及确认加入；不自动加入，也不丢失邀请上下文。
2. 点击未报名项目卡片，弹出紧凑选择层：个人参赛 / 加入战队 / 创建战队。个人参赛完成后直达本项目打卡。加入只展示本项目可加入队伍；创建只填队名与选填口号，项目从入口带入并显示。
3. 已报名项目卡片直接打开原打卡页，不重复选择参赛方式。卡片标记“个人参赛”或对应战队名称。
4. 组队广场在标题下放置现有样式的五项目页签；先显示“我在此项目的战队”，再显示可加入战队。创建按钮跟随当前项目。队卡显示固定项目、队名、人数、成员和人均成绩；已满、已加入、加载中、失败均有明确反馈。同项目已入队禁用其他加入入口，不影响其他项目组队。
5. 战队详情只展示所属项目的成员成绩、完成情况、人均与排名。成员能直接点击“去打卡”；邀请链接指向本项目战队。满员邀请显示满员信息，提供本项目其他队伍和个人参赛入口。
6. 排行榜保留项目切换与综合 / 个人 / 团队榜，战队行仅出现其绑定项目；当前用户所属战队按该项目高亮。
7. “我的”按已报名项目分组展示个人成绩、当前战队或“个人参赛”、去打卡 / 查看战队 / 去组队入口，不再只显示一个全局战队。

不重新增加此前删除的顶部副标题或“报名新项目”按钮。项目页签沿用现有视觉风格；操作按钮触控区域至少 44px，创建/加入有提交中禁用与原位错误提示。

## 两种方案比较

推荐“一队一项目”：项目归属直观，队员就是本项目参赛者，加入与人均口径一致；允许用户在不同项目自由选择伙伴。

可选“一队多项目”：保留全局队伍，再由队长选择队伍报名项目，但仍需区分队内哪些人参加哪些项目，同一队在不同项目的分母不同，解释和操作成本较高。

## 现有数据兼容建议

正式修改前备份数据库、图片并记录榜单。现有跨项目队伍按各项目当前已报名成员生成项目战队，同一批成员已有当天成绩、凭证不复制也不清除；按项目保留原人均与成绩。创建后无任何报名项目的旧队伍不自动替成员报名，保留原始数据并另行确认归属。已生成战报仍保持原快照。

用户已确认实施。通过新增按活动日期与项目的成员关系替代运行中的全局 team_id，旧表保留；检查创建/加入、人数限制、邀请、榜单、管理与导出入口。

## 验收重点

不同项目加入不同队、同项目重复加入与并发满员、加入自动报名、原成绩带入、人均分母包含未打卡成员、未报名与已报名卡片两种点击路径、满员/失效邀请、冻结控制、旧数据迁移前后成绩一致、五赛道与所有榜单切换、手机端完整操作。
